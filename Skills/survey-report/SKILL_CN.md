# survey-report（调研报告撰写）

## 概述

本技能指导**撰写 `Survey/report.md`**（调研综合报告）的流程。它读取 workspace 中已收集和分析好的数据，生成一份全面、结构清晰的调研报告，字数不设上限。

本技能**仅写入 `Survey/report.md`**，不会：
- 执行网络检索（请参考 `deep-search` 技能）
- 修改 `Inputs/raw/collected_papers.md`
- 修改 `Survey/surveyed.md`

## 输入数据源

撰写报告前，读取以下 workspace 文件作为输入：

| 文件 | 内容 | 如何使用 |
|------|------|----------|
| `Inputs/raw/collected_papers.md` | 结构化文献数据 | 提取论文元数据、统计信息和覆盖范围 |
| `Survey/surveyed.md` | 逐篇深度分析 | 主要内容来源 — 综合这些分析 |
| `Survey/human_feedback_survey.md` | 用户对之前调研的反馈 | 在修订报告中回应反馈（迭代模式） |

## 工作流程

### 1. 读取所有输入数据
- 读取 `Planning/task_breakdown.json` 了解研究范围和关键词
- 读取 `Survey/surveyed.md` 获取逐篇分析结果
- 读取 `Inputs/raw/collected_papers.md` 获取论文元数据和统计信息
- 如为迭代模式，读取之前的 `Survey/report.md` 和 `Survey/human_feedback_survey.md`

### 2. 分析与组织
- 按研究方向/主题对逐篇分析进行分组
- 识别跨方向的共性模式、关联和矛盾
- 梳理技术发展脉络
- 识别研究空白和未探索的机会

### 3. 撰写 report.md
- 按照下方定义的报告结构撰写
- 确保每个论断都可追溯到 `surveyed.md` 中的具体论文
- 尽可能使用量化数据

### 4. 保存输出
- 将报告保存到 `Survey/report.md`

## 报告结构（report.md）

报告必须遵循以下结构：

### 1. 调研概览
- 研究主题和范围
- 数据来源概要（论文总数、质量分布、覆盖领域）
- 使用的搜索查询（来自 `collected_papers.md` 的搜索概况部分）
- 方法论简述

### 2. 各方向调研结果
对每个识别出的研究方向：
- **方向标题和描述**
- **关键论文**：列出最相关的论文及其核心发现
- **技术路线**：总结该方向使用的方法
- **当前最优水平**：最佳方案是什么，为什么
- **方向小结**：该方向的关键要点

### 3. 核心概念与方法汇总
- 跨多个方向出现的共性主题
- 关键技术及其关系（如哪些方法基于哪些方法构建）
- 共同假设及其有效性

### 4. 技术空白与研究机会
- 文献中覆盖不足的领域
- 论文之间的矛盾或未解决的争论
- 现有方法的有前景但未探索的组合
- 当前主流方法共有的局限性

### 5. 结论与下一步建议
- 调研的关键要点
- 对创新阶段的推荐关注方向
- 基于空白分析的优先级建议

## 质量指南

- 每个论断必须有调研论文中的证据支撑
- 尽可能使用具体数字和指标（如"达到 95.3% 准确率"而非"达到较高准确率"）
- 明确区分已确立的事实和推测性观察
- 全文保持中立、分析性的语气

## 迭代协议

修订已有报告（非首次撰写）时：

1. 读取之前的 `Survey/report.md`
2. 读取 `Survey/human_feedback_survey.md` 获取用户的具体反馈
3. 根据反馈识别需要修订的章节
4. 修订报告 — 更新受影响的章节，保留未受影响的内容
5. 在报告顶部添加"修订说明"章节，注明变更内容和原因
